# Sport Tournament API

REST-сервис для проведения турнира на выбывание (single elimination).
Создаём турнир → регистрируем участников → генерируем сетку с посевом по рейтингу и
автопроходами (BYE) → вносим результаты матчей → получаем актуальную сетку, историю и чемпиона.

Участников может быть любое количество ≥ 2, не только степень двойки.

## Стек

Java 21 · Spring Boot 4.0.6 (web, data-jpa, flyway) · PostgreSQL 15 · MapStruct · Lombok · Maven

## Запуск

```bash
docker compose up -d      # PostgreSQL на localhost:5440
mvn spring-boot:run       # приложение на http://localhost:8081
```

Flyway накатывает схему при старте сам. Активный профиль — `standalone`
(`application-standalone.yml`: порт 8081, БД `jdbc:postgresql://localhost:5440/postgres`,
`postgres`/`postgres`). Креды контейнера переопределяются через `.env`
(`POSTGRES_USERNAME`, `POSTGRES_PASSWORD`, `POSTGRES_DATABASE`).

> У контейнера нет volume — данные живут, пока жив контейнер.

## Быстрый сценарий


Сетка, которая получится на шаге 3 (5 участников → сетка на 8):

```
1/4                     Semifinal            Final
Alice ──── BYE ────┐
                   ├── Alice vs ? ──┐
Dave  ┐            │                │
      ├── (READY) ─┘                │
Eve   ┘                             ├── Champion
                                    │
Bob   ──── BYE ────┐                │
                   ├── Bob vs Carol ┘
Carol ──── BYE ────┘     (READY)
```

Сразу после старта играбельны два матча: `Dave vs Eve` и `Bob vs Carol` — второй полуфинал
готов сразу, потому что оба его участника пришли по BYE. Alice как первый сеяный и Bob как
второй могут встретиться только в финале.

## API

| Метод    | Путь                             | Ответ                            |
|----------|----------------------------------|----------------------------------|
| `POST`   | `/tournaments`                   | `201` + `{id, name, discipline}` |
| `GET`    | `/tournaments?page=0&size=10`    | `200` + список турниров          |
| `POST`   | `/tournaments/{id}/participants` | `200` + участник                 |
| `POST`   | `/tournaments/{id}/start`        | `200` + состояние сетки          |
| `GET`    | `/tournaments/{id}/bracket`      | `200` + состояние сетки          |
| `POST`   | `/matches/{matchId}/result`      | `200` + состояние сетки          |
| `DELETE` | `/tournaments/{id}`              | `204`, каскадное удаление        |

Тела запросов:

```jsonc
POST /tournaments                    { "name": "Spring Cup", "discipline": "Table tennis" }
POST /tournaments/{id}/participants  { "name": "Alice", "rating": 1500 }
POST /matches/{matchId}/result       { "winnerId": 4 }
```

`start`, `bracket` и `result` возвращают один и тот же объект — полное состояние турнира:

```json
{
  "id": 1,
  "name": "Spring Cup",
  "discipline": "Table tennis",
  "status": "IN_PROGRESS",
  "createdAt": "2026-08-21T10:00:00",
  "startedAt": "2026-08-21T10:05:00",
  "finishedAt": null,

  "participantsCount": 5,
  "roundsCount": 3,
  "matchesCount": 7,
  "completedMatchesCount": 3,

  "champion": null,
  "participants": [ { "id": 1, "name": "Alice", "rating": 1500 } ],
  "rounds": [
    {
      "id": 1, "number": 1, "title": "1/4",
      "matches": [
        {
          "id": 4,
          "position": 0,
          "status": "COMPLETED",
          "bye": true,
          "slot1": { "id": 1, "name": "Alice", "rating": 1500 },
          "slot2": null,
          "winner": { "id": 1, "name": "Alice", "rating": 1500 },
          "nextMatchId": 2,
          "nextSlot": 1,
          "completedAt": "2026-08-21T10:05:00"
        }
      ]
    }
  ],
  "history": []
}
```

* `rounds` — вся сетка по раундам и позициям;
* `history` — только завершённые матчи в порядке завершения;
* `champion` — победитель финала, `null` пока турнир идёт.

## Правила и краевые случаи

| Ситуация                                                     | Поведение                                                     | HTTP  |
|--------------------------------------------------------------|---------------------------------------------------------------|-------|
| Повторный `POST /start`                                      | возвращается текущее состояние, вторая сетка **не** создаётся | `200` |
| Старт с < 2 участниками                                      | `tournament participant less than 2`                          | `400` |
| Участник после старта                                        | `Tournament already has been started or completed.`           | `400` |
| Результат матча, где известен один участник или ни одного    | `match is not ready: both participants are not known yet`     | `400` |
| `winnerId` не из этого матча                                 | `participant is not in this match`                            | `400` |
| Повторный результат / другой победитель на завершённом матче | `match is already completed`                                  | `400` |
| Несуществующий турнир или матч                               | `tournament not found by id` / `match not found by id`        | `404` |

Формат ошибки единый (`ControllerAdvice`):

```json
{ "message": "match is already completed", "errors": null }
```

## Принятые решения и почему

1. **Сетка материализуется целиком при старте.** `POST /start` создаёт все раунды и все
   `bracketSize − 1` матчей сразу, включая ещё пустые. Матч знает, куда уходит его победитель
   (`next_match_id` + `next_slot`), поэтому внесение результата — это одно присваивание в слот
   следующего матча, а не пересчёт всей сетки. Читается сетка тоже дёшево — одним запросом.
2. **Матчи создаются от финала к первому раунду.** Только так у следующего матча уже есть `id`
   в момент, когда на него ссылаются, — иначе пришлось бы делать второй проход с апдейтами.
3. **Статус матча хранится, а не вычисляется.** `PENDING` → `READY` → `COMPLETED`. Благодаря
   этому правило «нельзя внести результат, пока не определены оба участника» — это проверка
   одного поля, а не разбор состояния слотов на каждом запросе.
4. **BYE закрываются сразу при старте**. Матч с одним
   участником помечается `is_bye = true`, завершается и продвигает участника дальше прямо в
   транзакции старта. Сразу после `/start` сетка консистентна, и видно, какие матчи уже
   играбельны, а автопроходы честно попадают в историю.
5. **Повторный `/start` идемпотентен** — возвращает текущее состояние вместо ошибки. Клиенту
   при ретрае важен результат, а не то, кто первым дошёл до сервера; главное, что вторая сетка
   не создаётся.
6. **Результат матча неизменяем.** ТЗ разрешает выбрать между запретом и каскадным откатом —
   выбран запрет: завершённый матч не переоткрывается ни при каких условиях. Каскадный откат
   потребовал бы рекурсивно чистить все зависимые матчи вниз по сетке и уметь возвращать турнир
   из `COMPLETED` обратно в `IN_PROGRESS`, а это заметная сложность ради операции, которая в
   реальном турнире делается судьёй вручную и редко.
7. **Посев по рейтингу** (бонусный пункт). Участники сортируются `rating DESC NULLS LAST, id ASC`
   и раскладываются в порядке `[1, 8, 4, 5, 2, 7, 3, 6]`: первый сеяный встречает последнего, а
   первый со вторым сходятся только в финале. Порядок детерминированный — при равных рейтингах
   решает время регистрации, рандома нет, поэтому сетка воспроизводима.
8. **Один победитель на матч.** API принимает только `winnerId`: ничьих, переигровок и
   технических поражений в модели нет — в сетке на выбывание дальше проходит ровно один.
9. **PostgreSQL + Flyway, статусы — native enum-типы БД** (`tournament_status`, `match_status`).
   Схема версионируется миграциями, а недопустимый статус отсекается на уровне БД, а не только
   приложением.

## Что бы доделал, будь ещё день

1. **Тесты** — в первую очередь: генерация сетки для 8, 5 и 6 участников (число матчей и
   расстановка BYE), проход победителя до чемпиона, негативные кейсы. Ожидаемые числа:

   | Участников | Размер сетки | Раундов | Матчей | BYE | Реальных матчей в 1-м раунде |
   |------------|--------------|---------|--------|-----|------------------------------|
   | 8          | 8            | 3       | 7      | 0   | 4                            |
   | 5          | 8            | 3       | 7      | 3   | 1                            |
   | 6          | 8            | 3       | 7      | 2   | 2                            |

   Тонкость: H2 не понимает `CREATE TYPE ... AS ENUM`, так что интеграционные тесты требуют
   Testcontainers. Поэтому сначала вынес бы генерацию сетки (`seedOrder`, `nextPowerOfTwo`,
   раскладка по слотам) в отдельный `BracketGenerator` без JPA — тогда основные проверки
   становятся быстрыми юнит-тестами, а Testcontainers нужен только для одного end-to-end.
2. **Валидация входных DTO** — `@Valid`, `@NotBlank` на имени, обработчик
   `MethodArgumentNotValidException` (поле `errors` в `ExceptionBody` заведено именно под это)
   и fallback-обработчик, чтобы нарушение constraint'а БД не выходило голым `500`.
   Заодно `rating` в `CreateParticipantsRequestDto` должен быть `Integer`, а не `int`: сейчас
   участник без рейтинга получает `0` вместо `null` и встаёт в посеве выше безрейтинговых.
3. **DTO вместо сущностей** в `GET /tournaments` и `POST /participants` — сейчас наружу
   отдаётся JPA-сущность, и у участника в JSON едет вложенный турнир целиком.

## Структура проекта

```
src/main/java/example/com/
├── SportTournament.java              точка входа
├── controller/
│   ├── TournamentRestController.java
│   ├── MatchRestController.java
│   ├── ControllerAdvice.java         единый формат ошибок
│   ├── dto/                          record-DTO запросов и ответов
│   └── mapper/TournamentMapper.java  MapStruct, unmappedTargetPolicy = ERROR
├── domain/                           JPA-сущности, enum-статусы, исключения
├── repository/                       Spring Data JPA + JPQL для сетки и посева
└── service/
    ├── TournamentService(.impl)      генерация сетки, результаты, сборка ответа
    └── ParticipantService(.impl)     регистрация участников
src/main/resources/db/migration/      Flyway: tournament, participant, round, match
```

Модель данных:

```
Tournament 1 ─── * Participant
     │
     ├── 1 ─── * Round    (номер + название: 1/8, 1/4, Semifinal, Final)
     └── 1 ─── * Match    (позиция в раунде, два слота, победитель,
                           next_match_id + next_slot — куда проходит победитель,
                           is_bye — автопроход)
```
